# 信息来源与核验政策

## 本机当前的信息来源

| 来源 | 类型 | 是否实时 | 说明 |
| --- | --- | --- | --- |
| 用户填写的旅行需求 | 用户输入 | 是 | 出发地、日期、人数、预算、偏好、特殊需求 |
| 寰途本地知识库 | 静态整理 | 否 | 编写于 2026-10，目的地与规划方法，会过期 |
| 模型自身知识 | 模型陈述 | 否 | 可能过时或错误，必须标为待核实 |
| 实时搜索 API | 条件接入 | 取决于运行配置 | 支持免密钥网页适配器及 DeepSeek、博查、智谱、Tavily、Serper、SearXNG；成功命中后记录来源和读取时间 |
| 地图 / 路线 API | 未接入 | — | 当前路线图为基于行程数据的示意图，非实时地图 |
| 酒店库存 / 价格 API | 未接入 | — | 价格一律"待核实"，不代订 |
| 天气 API | 已实现 | 是，Open-Meteo | 超出预报范围时降级为去年同期气候参考，并明确标注“不是预报” |
| Google Calendar OAuth | 未授权 | — | 未配置 OAuth 客户端，仅提供导入链接 |
| Apple Calendar | 不支持直连 | — | 通过 .ics 导入系统日历 |

## 核验字段的处理规则

以下字段即使来自实时搜索，也必须显示来源并保留「待核实」边界，不允许出现模型伪造的查询时间：

- 天气、气温、降水、台风与预警
- 酒店房价、可订状态、评分与点评数
- 景点开放时间、闭馆日、门票价格
- 交通班次、末班车时间、车票余量
- 餐厅营业时间、是否需要预约、人均消费

只有当后端真正调用到对应 API 并拿到结果时，才会由后端写入 `checkedAt`（真实查询时间）。模型自己声称"已查询"的时间戳会被后端丢弃。

## 日期的含义

- `plan.meta.generatedAt`：本次方案生成时间（真实，后端写入）。
- `source.retrievedAt`：该来源实际被读取的时间（本地知识库为进程启动加载时间）。
- `verify.checkedAt`：某条时效信息被实时核验的时间；模型自报的时间不会写入，未成功调用实时来源时为 `null`。

## 日历的三种状态（界面必须区分）

- **已同步**：需要 OAuth 授权 + 用户逐次确认写入。当前不可用。
- **需要授权**：Google Calendar / Apple Calendar 尚未完成 OAuth，界面显示"尚未授权"。
- **可导入**：标准 `.ics` 文件下载 + Google Calendar 创建事件链接。任何人可用，无需授权。

不得把"可导入"写成"已同步"，也不得把"尚未授权"隐藏成默认已连接。
